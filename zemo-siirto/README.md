# ZEMO SIIRTO – static prototype

> **The main app is now the Next.js app in [`../zemo-siirto-web`](../zemo-siirto-web)**, which also holds the
> Supabase migrations (`zemo-siirto-web/supabase/`). This static version remains as a no-backend demo.

*Your car. Our driver. Your destination.* – Auton siirto Suomessa, luotettavasti.

Static website (no build step) + Supabase backend.

```
zemosiirto.fi
├── /                      landing page + instant price
├── customer/  login · dashboard · create-order · tracking
├── driver/    login · available-jobs · my-jobs · inspection · navigation · earnings · profile
└── admin/     login · dashboard · drivers · customers · orders · pricing · payments · settings
```

Every page has its own `index.html` (generated by `tools/build_pages.py`) and shares `app.js`, `style.css` and `config.js`.

## Two modes

| `config.js` | Mode | Data |
|---|---|---|
| empty (default) | **Local demo** | Stored in the visitor's browser. Admin → Settings → *Load demo data*. |
| Supabase URL + anon key | **Supabase** | Shared database, real logins (Supabase Auth). |

## Order flow

Customer creates order → pays → driver accepts (`accept_transfer`) → **pickup inspection** → navigation → start driving
→ **delivery inspection** (`complete_transfer` books the driver's earnings) → admin pays out (`create_driver_payout`).

## Connect to Supabase

1. Create a Supabase project (EU region, e.g. Stockholm or Frankfurt).
2. Run the migrations **in order** – SQL Editor (paste each file) or `supabase db push`:
   1. `../zemo-siirto-web/supabase/migrations/20261116000000_base_schema.sql` – tables, sign-up trigger, RLS
   2. `../zemo-siirto-web/supabase/migrations/20261117000000_driver_jobs_and_earnings.sql` – assignments, earnings, payouts, expenses
   3. `../zemo-siirto-web/supabase/migrations/20261118000000_app_api.sql` – all functions the website calls
3. Authentication → URL Configuration: Site URL `https://zemosiirto.fi`, and add
   `https://zemosiirto.fi/customer/login/` and `https://zemosiirto.fi/driver/login/` to Redirect URLs.
4. Project Settings → API: copy the **Project URL** and the **anon public** key into `config.js`.
   (Never the `service_role` key.)
5. Create the first admin: sign up at `/customer/login/`, then in the SQL Editor:
   ```sql
   update public.profiles set role = 'admin' where email = 'you@example.com';
   ```

### Before real customers use it

- **Payments are simulated.** `demo_pay_order` lets a customer mark an order paid. Connect a payment provider
  (Stripe / Paytrail) that confirms payments from a webhook with the service role, then run
  `update public.app_settings set allow_demo_payments = false;`
- **Photos and the licence image** are stored as file names only; add Supabase Storage uploads.
- Drivers' **expenses** (train tickets, fuel…) exist in the database and are included in payouts, but there is no page for them yet.

## Security model

- RLS is enabled on every table. Clients can only *read* rows they are allowed to see; all writes go through
  `SECURITY DEFINER` functions that check the caller's role and the order's state.
- Sign-up can only create `customer` or `driver` profiles; admins are promoted in SQL.
- Drivers don't see the customer's name, phone or contact people until they are assigned to the order.
- A driver can claim an order only once; a row lock + unique indexes stop two drivers taking the same job.

## Tests

- `../zemo-siirto-web/supabase/tests/run_local.sh` – 47 SQL checks (roles, RLS, pricing, race rules, earnings, payouts) on a throwaway Postgres.
- `tests/e2e.js` – full browser walkthrough of all three portals (Playwright):
  - local mode: serve this folder (`python3 -m http.server 8765`) → `node tests/e2e.js http://localhost:8765/ local`
  - Supabase mode against the real SQL: start Postgres with `../zemo-siirto-web/supabase/tests/local_supabase_stub.sql` + the migrations,
    then, inside `../zemo-siirto-web/` after `npm install`: `node supabase/tests/fake-supabase/server.js 8790 ../zemo-siirto` → `node tests/e2e.js http://localhost:8790/ remote`
